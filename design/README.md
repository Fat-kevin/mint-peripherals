# 外设中枢 · 静态视觉稿（Graphite Console）

> 这是**设计验证稿**，不是运行时页面。HTML/CSS 只用于在浏览器里看布局、对比度、密度和状态；
> 最终实现仍然是 WinUI 3 原生 XAML，不引入 WebView2 / HTML 运行时。
>
> 稿内数值（电量、DPI、固件）是示意数据，用来检查层级和状态色；不作为应用真实能力。

## 1. 设计任务

- 产品：Windows 桌面的三设备控制台（耳机、鼠标、遥控器）。
- 用户：一个人同时管理桌面上三台外设，通常只想知道“连没连、多少电、下一步点哪”。
- 主要任务：
  1. 5 秒内看清三台设备状态；
  2. 从设备中心直接进入最常用操作；
  3. 在单个设备页完成调整，不迷路、不误触；
  4. 低电量、离线、未接入能力一眼可辨，不靠猜。
- 窗口：固定 1280×840，不可缩放；内容不横向滚动。

## 2. 视觉方向

**Graphite Console（石墨仪表台）**：像一台放在桌上的小型控制台，而不是一组 SaaS 卡片。

- 深石墨底 + 蓝灰分层，近黑但不纯黑；
- 主按钮用暖象牙色，像硬件上的电源键；琥珀色只做“电量低/需要注意”的 LED；
- 三台设备各有信号色：耳机薰衣草、鼠标铜色、遥控器青绿；颜色只出现在设备身份、电量和选中态；
- 卡片少而整，靠 1px 边框、内高光和间距分层，不用大阴影/渐变；
- 数字用等宽数字（tabular），电量、DPI 这类读数不跳动；
- 一页只允许一个主操作；其余动作降级为次级按钮/文字按钮。

- 内容左对齐；标题与页面左边缘对齐；数字右对齐或按列对齐。
- 设备中心用**横向通道行**，不用三张等宽卡片：扫描快、可放更多真实状态、避免下半屏空白。
- 设备页统一“紧凑 hero + 主工作区 + 次级区域”，首屏先给状态和主操作。

### 2.3 与“默认 AI 稿”的区别（自查）

- 不做深色底 + 单一紫色强调；紫色只属于耳机，主操作是暖象牙色。
- 不做三张同构圆角卡片；设备中心是带信号条的通道行 + 底部工作面板。
- 不用全大写小标签、编号装饰、`01/02/03` 和每条链接都加 `→`。
- 不堆渐变、玻璃和阴影；只用 1px 边框、内高光和局部设备色晕。
- 保留大数字，但大数字必须对应真实读数（电量/DPI），不是装饰性 KPI。

## 3. 页面结构

### 设备中心
1. 标题 + 同步状态 + 刷新。
2. 连接状态 rail：3 台设备节点，显示设备名、连接方式、状态。
3. 三条设备通道：产品图、名称/连接方式、电量、关键状态、打开按钮。
4. 底部：快捷操作（查找耳机 / 鼠标 DPI / 接收测试）+ 通道健康（SPP/HID++/Sidecar）。

### 耳机
1. 标题 + 设备名 + 已连接/SPP/固件 chips。
2. Hero：产品图 + 左/右/盒三路电量 + 查找耳机主操作。
3. 左：降噪模式、EQ、5 个快捷开关；右：连接状态、设备信息、重新连接/断开。
4. 查找耳机保留 5 秒可取消的语义。

### 鼠标
1. 标题 + 低电量提示 + 刷新。
2. Hero：产品图、当前 DPI、轮询率、板载状态、低电量建议。
3. 左：DPI 滑杆 + 5 个档位 + 当前档位；右：设备信息、板载配置、配置名称。
4. 下：按键映射；底部统一“应用设置/刷新鼠标”。

#### 按键映射列（设备驱动）

不同鼠标的按键数量、名称和顺序都不同，所以这一列不预设 6 行，也不假设左/右键一定锁定：

- 只读取 `MouseControls.Buttons`，按设备返回的顺序渲染；数量显示为“设备返回 N 个”，不写死“6 个可配置按键”。
- 每格 = 设备按键名 + 当前动作下拉。`ButtonMapping.Key` 是设备/槽位名，`Action` 是当前动作，`Id` 是设备槽位。
- 0 个按键：显示空状态“此鼠标没有返回可配置按键；性能与设备信息仍可用”，不显示空白行。
- 1–8 个：2 列紧凑网格；超过可视行数在映射区域内滚动，不把页面撑长。
- 最多按协议上限 16 个静态单元；只更新 `Visibility`、`Text`、`SelectedValue`，不在 15 秒刷新里重建 `ItemsSource` 或控件树。
- 设备返回未知动作时，下拉显示“未识别（保留原值）”，应用时保留原动作，不猜测、不伪造。
- `OnboardProfileWritable=false` 或写入未授权时，整表禁用并显示原因；不逐行伪造 lock。
- 非 G304/G305 型号只保留左/右/中键的通用名，其余按键以“按键 N”槽位显示，避免把某一款鼠标的侧键/DPI 名套到所有设备。

### 遥控器
1. 标题 + 电量 + 刷新。
2. 连接条：设备选择、扫描、断开、引擎状态。
3. 左：按键图 + 选中键；中：当前键的三个手势 + 修改/测试；右：语音链路。
4. 下：全部映射（可滚动/筛选），显示 13 键 × 3 手势；静态稿只露出 4 行，避免把表格压成密密麻麻的 9px 字。

### 设置
1. 两列布局：模块 / 通知；写入授权 / 备份与恢复。
2. 模块开关直接说明关闭后的后果，不只写“启用/禁用”。
3. 写入授权单独成组：关闭是服务层拒绝写入，不是把按钮变灰。
4. 低电量阈值与通知放在同一组；备份、恢复默认、诊断入口保持低频但可达。
5. 右下角固定诊断条，不把低频操作塞进主工作区。

## 4. 人机工程检查

- 点击目标：主按钮 34–40px 高，设备/设置行 ≥ 32px，导航项 38px，密集表格行 30px；不把文字链接当主操作。
- 阅读顺序：标题 → 状态 → 主操作 → 细节；同屏最多 3 个层级。
- 状态双编码：颜色 + 文字（已连接/离线/电量低）；色盲可读。
- 数字：等宽数字，电量/DPI 右对齐；百分比和单位不拆行。
- 反馈：保存状态、倒计时、低电量建议都在操作附近；不依赖弹层。
- 防误触：查找耳机、断开等一次性/破坏性动作与主设置分开；查找有 5 秒取消语义。
- 滚动：鼠标映射超过 4 行时在映射区域内滚动；遥控器全量映射区域内部滚动；其余页面在 1280×840 内完整呈现。
- 键盘：原生控件保留 Tab 顺序、焦点描边、ComboBox 键盘选择；静态稿只表达视觉。

## 6. 从静态稿到 XAML

这不是“照着截图重画”，而是把静态稿的结构翻译成原生控件，并保留现有稳定性红线。

| 静态元素 | WinUI 3 实现 | 注意 |
|---|---|---|
| 固定窗口 | `AppWindow` 尺寸在 `InitializeComponent` 前设置一次 | 不在运行中 resize / 最大化 |
| 左侧导航 | `NavigationView` 或自绘 `Grid + Button` | 当前页只改选中态，不重建页面 |
| 设备通道行 | `Grid` + 透明底 `Button` 覆盖整行 | 行内“打开”是视觉提示，整行可点 |
| 电量条 | `ProgressBar` 自定义模板 + `Border` 刻度 | 不用 `BitmapImage`；值来自快照 |
| 耳机 ANC / EQ | `ComboBox` | `SelectionChanged` 内先读后写，失败回滚显示 |
| 快捷开关 | `ToggleSwitch` | 去掉默认 On/Off 文案，保留文字状态“开/关” |
| 鼠标 DPI | `Slider` + 5 个 `Button` 档位 | 档位与滑杆双向同步，显式“应用设置” |
| 鼠标映射 | 最多 16 个静态 `ComboBox` / 行内选择；`ItemsSource` 只在构造时设置一次 | 不用 Flyout；不预设按键数；按 `Buttons` 显示/隐藏；未知动作保留原值 |
| 遥控器按键图 | `Image` + 透明 `Button` 叠点 | 选中态用 2px 琥珀描边 + 文字“已选” |
| 手势编辑 | 行内 `ComboBox` 或列表 | 不用 `ContentDialog` / `StartBringIntoView` |
| 全部映射 | `ScrollViewer` + `Grid` 行 | 只滚动表格区域；单元格高 ≥ 30px |
| 设置分组 | 两列 `Grid` + `StackPanel` | 开关保存后立即生效；不弹确认框 |
| 15s 刷新 | 只更新 `TextBlock` / `ProgressBar.Value` | 不重建 `ItemsSource` / 图片 |

### 实现顺序建议

1. 先做设备中心（信息架构和导航）→ 2. 耳机页（控件最多）→ 3. 鼠标页（写入确认）→ 4. 遥控器页（按键图和表格）→ 5. 设置页（低频设置与诊断）。
5. 每页完成后只构建一次；全部完成后再启动一次做整窗验证，避免反复拉起应用。
