# 三个原项目的功能对齐审计（2026-10-21）

> 只读审计结论 + 本轮的取舍。审计对象：`NICEHCK_OriG-in`（耳机 SPP）、
> `openmouse`（鼠标 HID++）、`remote-mic-app-windows`（遥控器/语音）。
>
> 结论先行：三个项目的**协议/引擎能力已经全部接进整合应用**；真正缺的是少量
> 桌面快捷、需要逆向/真机确认的写入能力，以及首次向导/导入导出这类体验项。
> 本轮没有为了“看起来完整”而伪造任何设备能力。

## 1. 审计边界

- 只读源码、文档和构建产物，不启动原项目，不改用户配置。
- 耳机 external 快照的 7 个关键文件与原项目 SHA-256 一致；遥控器 vendored
  crates 与原项目逐文件一致（仅多一个 `enhanced_capture_enabled()` getter）。
- 因此差异只在 **App 层接线/UI**，不在协议/引擎层。
- 真实写入是否生效必须真机验证；本页只判断“入口、调用链、回读/错误处理”是否完整。

## 2. 耳机（NICEHCK_OriG-in / YUANDAO）

### 已对齐

| 能力 | 整合应用入口 | 判定 |
|---|---|---|
| 自动发现、连接、断线重连 | 后台服务 | 已对齐 |
| L/R/盒分量电量 | 耳机页三张电量卡 | 已对齐（只读） |
| 左右耳充电状态 | 电量卡副文本 | 已对齐（只读；盒恒 Unknown） |
| 固件版本 | 耳机页副标题/连接卡 | 已对齐（只读） |
| 六态 ANC | 耳机页下拉 + 写入回查 | 已对齐（实验/风噪需真机） |
| 七档 EQ | 耳机页下拉 + 写入回查 | 已对齐 |
| 游戏/低延迟/双连/入耳/抗风噪 | 五个开关 + 写入回查 | 已接入；V1/V2 分流见限制 |
| 查找耳机 | 5 秒可取消倒计时 | 已对齐（交互简化为页面内倒计时） |
| 模块/写入闸门 | 设置页 | 已对齐 |
| 连接/低电/写失败通知、日志、诊断包 | 应用服务 | 已对齐（比原项目多诊断包） |

### 明确不加入

| 项 | 理由 |
|---|---|
| OTA/固件升级 | 官方专有 oid/flash 流程未逆向，失败可致设备变砖；收益高风险极高 |
| 触控/手势配置 | `0x0203` payload 是对象且未坐实，盲写可能破坏手势；需要抓官方 App 报文 |
| codec 切换 | 无可靠查询、可能断音/重连；原项目也从未上 UI |
| 盒充电精确状态 | 协议和官方 App 都不建模；猜测字节等于伪造 |
| 声道/绝对音量 | 协议无 opcode，音量归 Windows/AVRCP |
| 多点设备列表 | 协议只有 `0x0105` 开关，没有设备枚举/当前设备 opcode |
| 分量电量历史图表 | SPP 分量不落库，成本高、价值低 |

### 已知限制（不是“已实现”）

- 五个快捷开关的 **V2 帧分流**尚未完成：当前始终发 V1；本机固件 4.8 是否
  接受 V1 需要真机验证。没有抓包前不盲发 V2 字节。
- 提示音音量：协议有构帧/状态字段，但 set payload 和范围未确认，未接线。
- 托盘 ANC 快捷菜单、手动重连/断开：属于桌面便利项，本轮没加；现有自动重连
  和页面状态已能覆盖主要路径。
- 查找耳机的停止命令是 best-effort；关闭写入时页面明确提示，不假装鸣响。

## 3. 鼠标（openmouse / Logitech G304）

### 已对齐

| 能力 | 整合应用入口 | 判定 |
|---|---|---|
| HID++ 发现/读取 | 鼠标页 | 已对齐 |
| 电量、当前 DPI、轮询率、固件 | 鼠标页 | 已对齐（只读） |
| 当前 DPI、轮询率、5 档 DPI、当前档位 | 鼠标页写入 + 回读 | 已对齐 |
| 板载 profile 名称/模式 | 鼠标页 | 已对齐 |
| 按键映射（G304 当前 6 键） | 鼠标页 | 已对齐；未知动作保留原值 |
| 写入闸门/型号校验 | 服务层 | 已对齐；非 G304/G305 只读 |

### 明确不加入

| 项 | 理由 |
|---|---|
| OpenMouse 的 AGPL 代码/94 驱动/158 型号表 | 协议事实可参考，代码不能直接复制进本项目 |
| 灯光/宏/高级手势 | G304 无灯、无宏；跨型号能力差异大，未验证 |
| profile 导入导出、多 profile 编辑 | 需要额外文件选择和兼容性设计；当前只读展示已有 profile |
| DPI 值的完整枚举 UI | 服务只暴露 min/max/step；遇到非均匀档位时尚未改成受支持值下拉（已知限制） |

### 已知限制

- `AppSliderStyle` 的 DPI 滑块按 min/max/step 走，某些设备的档位不是均匀步进，
  可能落到不受支持的值；应用时服务会回读/校验，但 UI 还不是“只允许合法值”。
- 按键动作空间是 18 个预设，没有键盘 HID 全量/修饰键录入；高风险且非本轮 UI 范围。

## 4. 遥控器 / 语音（remote-mic-app-windows）

### 已对齐

| 能力 | 整合应用入口 | 判定 |
|---|---|---|
| 引擎启停、自动连接、扫描/连接/断开 | 遥控器页连接条 | 已对齐 |
| 电量/型号/引擎状态 | 标题、连接条 | 已对齐（只读） |
| 13 键 × 3 手势读取 | 映射表 | 已对齐 |
| 单元格编辑动作 | 内嵌编辑面板 + 保存回读 | 已对齐；保存后强制回读 |
| 单击/双击/长按测试 | 映射卡 | 已对齐（仅可注入动作） |
| 接收测试（10 秒） | 映射卡 | 已对齐 |
| 音频端点选择 | 语音卡 | 已对齐 |
| 增益写入 | 滑块（0–24）+ 应用 | 已对齐；无读回 API，页面明确提示 |
| 四种语音工具 + 按住说话热键 | 语音卡 | **本轮修复**：豆包/微信/Vokie/其他，不再写坏枚举 |
| 全按键支持（Helper） | 开关 + 状态 | 已对齐 |
| 写入闸门、开机自启、诊断包 | 设置/服务 | 已对齐 |
| 其他工具快捷键文件备份 | 设置→备份 | **本轮补入** `other-voice-hotkey.json` |

### 明确不加入

| 项 | 理由 |
|---|---|
| 嵌入 Tauri/WebView2 或复用 Vue 页面 | 工作区红线；固定窗口 + WinUI 对 WebView2 崩溃敏感 |
| 应用内更新器/预览通道 | 未签名安装器/回滚链路风险高；发布走独立安装包 |
| 云同步/在线转写/语音内容缓存 | 隐私红线；原项目也交给第三方输入法 |
| 自动安装 VB-CABLE / 改系统默认设备 | 需要管理员/UAC 且改全局状态；原项目明确不做 |
| 关开蓝牙无线电/自动重新配对 | 会断开用户全部蓝牙设备，原项目已移除 |
| 聚焦输入框/学习输入框 | 原项目自己用 feature flag 关闭；UIPI/焦点风险高 |
| 自定义快捷键录入 | 原项目因问题隐藏；WinUI 键盘钩子冲突风险高 |
| 系统 `FileSavePicker` 导入导出 | 无包身份会挂起；如做需固定目录/Win32 对话框 |

### 已知限制

- `mappings.save` 的 sidecar 实现仍可能在写盘失败时返回成功；App 已加
  **保存后 `mappings.config.get` 回读比对**，但无法完全替代 sidecar 的规范化。
- 增益没有 `voice.gain.get`：页面不回读旧值，移动滑块后按 0–24 dB 写入。
- 按住连续执行（holdRepeat）、OK 5 秒上下文点击、映射总开关、首次向导、
  打开应用/聚焦输入框动作：引擎已支持，但 UI/客户端未接；本轮不扩张编辑面板。
- 语音运行态（voiceState/audio.phase/lastError）目前只用于引擎状态，页面没有
  单独诊断区。

## 5. 本轮实际改动

- 主题：新增设置页「外观」入口（深色/浅色/跟随系统），`Root.RequestedTheme`
  运行时切换；代码构造的画笔统一走 `AppTheme`，缓存页通过 `IThemeAware` 刷新。
- 状态图标：新增 `Controls/StatusChip`，用自绘矢量（时钟/勾/断线/警告/错误）
  替代 6px 圆点；设备中心三张卡、遥控器页、设置页和页脚统一使用。
- 遥控器：修复语音工具枚举；增益上限 24、加不回读提示；保存后回读；
  `mappings.test` 的 skipped 文案不再误报“未配置”；断开只依赖引擎连接。
- 备份：补入 `other-voice-hotkey.json`。
- 设备中心：遥控器卡使用真实产品图，不再只显示通用遥控器字形。

## 6. 仍需真机验证

1. 耳机 ANC 六态（含实验/风噪）、EQ 七档、五个开关是否真实生效；查找鸣响/停止。
2. 鼠标 DPI 档位写入后回读、按键映射保存/回读；非 G304 只读边界。
3. 遥控器四种语音工具各跑一次“按住语音键→上屏”；24 dB/重启读回；全按键 Helper；
   映射保存回读与失败提示。
4. 切换深浅色后逐页检查：标题栏按钮、导航、下拉、开关、InfoBar、状态胶囊、
   设备卡和映射表；至少做 3 轮页面轮转。
5. 固定 1280×840 下新增/改动的控件不裁切；闲置 10 分钟、最小化/恢复、二次启动。

## 7. 结论

- 三个项目的**协议/引擎层功能**已完整接入；不是“缺功能”，而是少量高风险写入
  未在缺少真机验证时硬上。
- 本轮优先修了**会直接让用户觉得功能坏了**的遥控器回归，并补齐主题、状态图标、
  保存回读和备份白名单。
- 未接入项都给出了理由：需要破解/真机验证、会改系统全局状态、或属于原项目也没有的
  低价值桌面差异。没有用假数据或假成功填充界面。
